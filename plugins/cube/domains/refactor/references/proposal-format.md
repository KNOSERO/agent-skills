# Proposal format

Load only when at least one justified proposal must be presented to the user.

Every proposal contains all fields below and receives a stable ID. Start with `T1`, then `T2`, `T3`, and so on. Never reuse an ID for a different meaning; a later finding receives the next ID.

| ID | Priority | Location | Problem | Proposed change | Benefit | Risk / dependencies | Verification |
| --- | --- | --- | --- | --- | --- | --- | --- |
| T1 | … | … | … | … | … | … | … |

Order proposals by actual impact. Present enough context for an informed selection, but do not implement before the user selects IDs. `documentation-guidelines` controls wording, density, and presentation; this format controls the required content.
