# Information structure

Use this reference for a larger rewrite or when the document's structure needs deliberate selection.

## Select the structure

Start from the reader's task, not from a fixed template. Identify:

| Question | Decision |
| --- | --- |
| What must the reader know first? | Put it in the opening paragraph, compact table, or first steps. |
| Which information is parallel? | Use a table or list. |
| Which information is sequential or relational? | Use a process description or diagram. |
| Which details are conditional? | Put them after the main path under a focused heading. |
| Which facts are uncertain? | Omit or label them explicitly. |

A useful optional progression is:

```text
What is it? → Why does it matter? → Important elements → How it works → Variants → Takeaway
```

Use only the stages that answer the reader's question.

## At-a-glance sections

For a technical element, add a short property/value table near the beginning when it enables quick orientation. Typical properties include purpose, input, output, owner, transport, authentication, primary key, or consumers. Adapt the properties to the element; do not require the section everywhere.

## Updating an existing document

Preserve useful confirmed information and local conventions. Reorder or rewrite only within the requested scope. Remove repetition and unsupported claims, but do not remove knowledge that is still used as a reference without checking its purpose.
