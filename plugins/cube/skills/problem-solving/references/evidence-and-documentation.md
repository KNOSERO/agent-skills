# Evidence and documentation

Load this reference when documentation materially affects requirements, contracts, expected behavior, source-of-truth interpretation, or conflicts with implementation or runtime evidence.

Treat relevant README files, requirements, ADRs, API contracts, schemas, runbooks, and process documentation as first-class evidence. Compare their claims with code, tests, configuration, schemas, and runtime evidence. Record the evidence status and material consequences of each source.

When sources conflict, expose the incompatible interpretations and the impact of each. Do not silently choose a source of truth or treat one artifact as authoritative merely because it is convenient. Use `grill` when resolving the conflict requires a product, project, design, compatibility, or source-of-truth decision. Omit or label details that remain unconfirmed.
