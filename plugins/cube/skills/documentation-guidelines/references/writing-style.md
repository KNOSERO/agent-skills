# Writing style

Use this reference for a substantial technical explanation, wording review, language decision, or concise developer-facing text.

## Write for scanning

- Lead with the answer or action.
- Keep sentences and paragraphs short.
- Keep one main idea per paragraph.
- Use headings that describe the information below them.
- Use lists for ordered steps and parallel choices.
- Use tables when the same properties recur across items.
- Define unfamiliar terms at first use.
- Prefer the smallest representation that preserves meaning, clarity, conditions, and risks.
- Reveal details progressively so the reader can stop after obtaining a sufficient answer.

Remove filler, repetition, obvious statements, long introductions, and summaries that merely repeat the document. Keep examples only when they reveal behavior that prose alone would obscure.

Do not add detail merely because it is available. Prefer high information density over length, but do not compress away behavior, decisions, dependencies, exceptions, or risks.

## Language precedence

Use this order:

1. explicit user requirement;
2. repository or project documentation rules;
3. language of the document being updated;
4. conversation language.

Repository files follow the repository's language. User-facing explanations follow the conversation language unless the user requests another language.

## Evidence wording

State confirmed behavior directly. Distinguish requirements, observed behavior, assumptions, and open questions. Use a short qualifier such as `Unconfirmed` only when the uncertainty is relevant to the reader's decision.
