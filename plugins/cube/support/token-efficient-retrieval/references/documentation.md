# Documentation retrieval

Treat documentation like source code. Start with metadata, table of contents, headings, or an index; search exact API names, configuration keys, error text, and distinctive terms; then retrieve the relevant section and only related sections needed to resolve ambiguity.

Use:

`index/headings → keyword search → relevant section → related section → full document`

Prefer anchors, page/line ranges, and section titles as pointers before copying prose. For large API or product documentation, identify the version and component first. Read the full document only when requirements, cross-references, or version interactions cannot be established locally. Summarize the applicable rule and retain its source location.
